# iOS 历史与后台恢复排查

## 已确认

录屏连接的是另一台远端服务器。约 14 秒录屏中，已有对话在切回前台后两次被历史加载界面替换；这能确认用户感知到重复加载，不能据此确定远端请求耗时或服务端版本。

iOS 当前会在没有 Agent 保活任务时主动挂起后台连接；回到前台重新连接。后台保活额度到期也会挂起连接。本次保留这一生命周期策略。

代码中发现主动挂起不经过普通连接失败回调，旧会话激活标记可能被保留。收到新的 hello 后先进入等待快照状态，再调用激活函数；旧标记会让激活函数跳过订阅。因此存在等待快照但没有重新订阅的路径。

## 本次修复

- 每个新的 hello 清除旧连接的会话激活标记，允许重新订阅。
- 已有可用对话行时，历史同步状态不再被解释为首屏准备状态。
- 共享 History Store 对完全相同的持久快照只更新加载及分页状态，不再发送完整替换事件，避免重复重建投影和 UIKit 列表。
- 相同持久历史仍可携带新的生成前缀；iOS 单独恢复该前缀，避免遗漏或重复。
- 历史格式变化、真实内容变化和首次空快照仍执行原有校验与替换流程。

没有增加磁盘历史缓存，没有修改网关或 Host，没有取消后台断连策略。

## 验证与尚未确认的部分

共享测试 179 项通过，iOS XCTest 171 项通过。新增回归覆盖相同快照不重发替换、分页信息更新、有内容时恢复不进入首屏准备，以及空持久历史下生成前缀仅恢复一次。

尚未连接用户的远端服务器复现。当前本机网关代码将 RC2 follow 首屏限制为最近 12 条消息，并对发送给 App 的持久历史窗口设置 256 KiB 预算；这一配置不能证明远端部署已包含相同优化。首次加载慢仍需核对远端 Mobile Gateway 的版本或 commit，以及其请求与响应耗时。单条不可分割事件、生成前缀及其他快照字段可能使完整响应超过该历史窗口预算。
