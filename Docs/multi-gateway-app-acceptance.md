# Mobile 多网关接入与人工验收

日期：2026-09-11。范围：iOS、Android 的多主机保存与切换；每次只保留当前主机的业务连接。

## 使用方式

1. 首页品牌标识下方新增主机栏，显示当前名称、设备图标和连接指示灯。
2. 点击主机栏打开历史列表。点击一台主机即可切换；导航回首页并加载该主机的会话、工作区及能力。
3. 首页右上角钥匙菜单支持扫码与手动导入；主机切换面板仅显示历史主机及编辑、切换操作，不提供新增配对入口。新增配对成功后才切换当前主机；失败保留原主机资料。
4. 名称优先使用本地别名，其次使用认证后的 `gatewayName`，旧网关回退到地址中的主机名。编辑时留空恢复服务端名称。
5. 现有协议没有服务器/PC 类型字段。App 以公网地址/局域网地址给出初始图标，可在“编辑主机”中改为电脑或服务器。
6. 绿灯表示当前连接正常或最近一次短暂鉴权探测成功。非当前主机只在列表打开且 App 在前台时探测，最多两台并发，每个候选地址最多约 3 秒；每轮结束等待 30 秒再检查。灰灯表示当前未确认在线，也可能是网络不可达、网关关闭、凭证失效或身份不一致。

## 隔离与兼容

- 每台主机拥有稳定的本地 ID。token 通过该 ID 分开保存：iOS Keychain；Android Keystore 加密存储。安装级设备 ID 继续共用。
- 每次切换都关闭旧控制/会话连接、取消旧请求与投影订阅，创建独立的 AppStore 或 AndroidAppGraph。旧异步回调只能触达旧容器，不会复用新主机的连接。
- 会话列表、工作区选择、图片缓存和已下载文件索引按本地主机 ID 隔离。工作区、模型、能力、任务、Goal、审批与文件状态在新容器中重新加载。
- 切换会返回首页并清空页面级临时输入、待发送图片、未提交的审批/问题表单；这些内容不会带入另一台主机。切换连接不会停止服务器上已经启动的任务。
- 旧单网关配置幂等迁移，保留原 token、会话列表、工作区选择、图片缓存及下载位置索引。旧存储保留以便排查迁移问题。
- 新旧协议均保留 `version: 2` 配对、`dsh-mobile-v1`、`hello.protocol: 3`。旧插件缺少身份时使用本地 ID；新身份必须为 UUID v4，二维码/paired/control hello/conversation hello 必须一致。已有身份不能降级为空身份。
- 同一 gatewayId 重新配对更新原记录及凭证；不根据名称合并。最新二维码提供本次认可的候选地址集合，不自动吸收未认证地址。
- 重连只在该主机认可的地址中进行，使用有界退避和候选地址切换；一次性配对码失败不自动重试。握手重定向被拒绝，凭证不会随跳转转发到其他来源。
- 收到 paired 后必须成功保存 token 才能继续；未返回 token 的配对不能只凭 hello 成功。

## 人工验收准备

- 准备一台服务器 A、两台 PC B/C，使用包含 Gateway 第一阶段修改的插件构建；每台具有不同 gatewayId，配置容易辨识的名称并开启常驻模式。
- 每台创建不同的测试工作区和会话。至少 A/B 构造相同 sessionId / workspaceId 的独立测试资源，分别设置不同标题、消息和文件内容。
- 在 iPhone 和 Android 手机上分别完整执行清单；记录 App/Gateway 版本、设备、网络和结果。
- 公网地址使用有效 WSS；LAN 地址必须手机可达。测试时不要公开管理接口、真实 token 或二维码。

## 人工逐项检查

- [ ] **旧配置升级**：从原单网关版本升级，原主机、凭证、会话及工作区选择保留；连续重启两次没有重复资料。
- [ ] **添加三台主机**：依次扫码 A/B/C，重启 App，列表保留三台且各自可连接；新增失败不会覆盖之前的主机。
- [ ] **名称与图标**：检查服务端名称；分别修改本地别名、恢复默认名称；将 A 设为服务器、B/C 设为电脑；重启后保持。
- [ ] **主机管理交互**：普通状态每行只有在线指示灯；点击“编辑”后 radio 出现在主机图标前，铅笔从右侧滑入，右上角保持为空，列表不显示排序拖拽条。
- [ ] **选择删除文案**：选择一台时右上角显示红色“删除”；选择两台或更多时显示红色“批量删除”；取消全部选择后按钮消失。
- [ ] **基本切换**：A→B→C→A，每次名称、工作区路径、会话、模型和能力属于当前主机。点击离线主机后不得显示上一台的工作区、任务、审批或文件。
- [ ] **相同资源 ID**：在 A/B 的同 ID 会话内分别写入不同测试内容，来回切换并打开历史；标题、消息、图片、任务、Goal、文件下载标记完全分开。
- [ ] **切换时旧响应迟到**：在 A 加载大历史/图片/文件或等待创建会话时切到 B；A 的迟到内容与错误不得跳转或覆盖 B 的页面。
- [ ] **写操作归属**：分别在 A/B 测试发送、停止、重命名、归档、审批、提问回答和文件操作，服务端日志确认只发往目标主机。切换后不会把前一台的临时输入提交到后一台。
- [ ] **探活灯**：打开列表，观察多台在线；关闭 A 的 Gateway 或断开 A 网络，等待一轮探测后 A 变灰，B/C 不受影响；恢复后可重新变绿。
- [ ] **前后台**：列表关闭、App 后台时不持续探测历史主机；返回前台并打开列表恢复检查。正在当前主机执行任务的既有后台行为正常。
- [ ] **凭证撤销**：在 A 撤销手机，A 连接失败/提示重新配对且不会无限快速重试；切 B/C 仍可正常操作。
- [ ] **重复配对**：重新生成 B 二维码并导入，资料数量不增加，本地别名保留，新凭证生效，旧通道关闭重建；A/C 不受影响。
- [ ] **候选地址**：给 A 配置两个手机可达地址，先连接成功，再断开首选网络；只在认可的候选地址之间恢复，不新增重复主机。再验证二维码首选地址不可达时明确失败，须重新生成/选择可达配对码。
- [ ] **身份反例**：测试实例的可信地址返回另一个 gatewayId，或二维码带 ID 但 hello 不带 ID，App 停止业务并保留原身份。修改名称不能绕过此检查。
- [ ] **地址反例**：导入公网明文 WS、带账号/查询/fragment、监听地址或超过 16 个候选地址的二维码，App 拒绝；握手跳转不会将 token 发送到新地址。
- [ ] **旧插件**：使用不含新增字段的旧 v2 二维码仍可连接，随后添加新插件主机并切换，数据各自隔离。
- [ ] **失败回退**：新配对超时、无效/过期配对码、配对不返回 token 时不会新增成功记录；原主机资料仍可选择。重复配对已轮换 token 的同一台失败时，重新生成二维码恢复。

## 可重复的模拟器冒烟

```bash
python3 scripts/multi_gateway_smoke_server.py
```

脚本只监听本机 18781/18782，打印 iOS Simulator 与 Android Emulator 各自的测试配对字符串，名称为 `Smoke A` / `Smoke B`。两台均使用 `same-session`、`same-workspace`，正文标题及路径分别包含 A/B。依次导入并切换，检查对应工作区和会话。

这是测试夹具，使用可重复的固定测试配对码，不验证真实 Gateway 的一次性配对、安全存储故障或任务执行；也不支持发送/删除等业务写操作。不要部署到公网。结束后 Ctrl-C 停止，模拟主机的灯应在后续探测中变灰。

## Android 新建会话响应修复

Android 原先在按钮协程中直接对 `GatewayRuntime.events` 调用 `first` 等待 `session-created`，与持续运行的投影消费者竞争同一个单消费者事件流。服务端已经创建 Session 时，投影消费者可能先取走响应，导致本机等待至超时、不跳转；等待期间再次点击还会遇到进行中的同类请求。

修复后，唯一的 Runtime 消费者在继续投影前把匹配 `requestId` 的创建响应交给按钮协程。响应先到或后到都能完成等待，随后选中新 Session、订阅、请求历史与会话控制项，并进入对话页。诊断日志的安全类型白名单也补充了 `session-create` 和 `session-created`。

## Android 回复复制按钮修复

Android 的最终回复会替换流式正文但保留原 `stream-` 消息 ID，以维持 LazyColumn 行稳定。旧界面只检查 ID 前缀，因此把已经完成的回复永久当成生成中，遗漏了底部复制按钮。现在结合会话运行状态和最近一条用户消息定位当前正在生成的回复：只暂时隐藏这一条的复制按钮，上一轮和已经结束的回复均显示。
