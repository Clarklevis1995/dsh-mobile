## 1. 最终交付目标

把当前验证性质的鸿蒙客户端推进为**采用 ArkUI 原生界面、复刻现有产品 UI、连接真实 Harness 后可以日常使用的聊天客户端**。

“完成”同时包含三件事：

1. **界面对齐**：冻结的现有产品页面、导航、布局、主题、主要组件、交互状态与动效全部有鸿蒙实现；不能以当前深色纯文本验证页或展示用设计图代替成品。
2. **业务闭环**：从配对、选择主机和工作区、进入会话，到发消息、阅读回复、回答问题、处理审批、传输附件、离线阅读和恢复连接，均能实际操作。
3. **可交付**：有可安装 HAP、可重复的测试、逐页对照截图、真实网关验收记录和已知限制。模拟器、测试夹具及真机结论分别记录。

当前默认以 **Android 现有产品源码的布局与交互为主基准，iOS 同期实机／模拟器截图作为品牌视觉补充**。原因是两端已经做过产品 UI 对齐，Android 的移动端结构更便于映射到鸿蒙。P0 冻结后按该版本实施，不追随其他分支未经确认的后续改动。

不要求复制 iOS 系统自身的权限弹窗和系统字体，也不移植 Compose、UIKit 或 AGSL。相机、相册、文件选择、分享等使用鸿蒙系统组件；应用内的品牌、层级与交互需对齐。无法等价实现的效果必须在差异表中说明并单独验收，不能自行省略。

## 6. 文档发现结果与允许使用的实现入口

本表是已查证的现有入口，不代表所有能力已在鸿蒙适配。执行每阶段前仍需读取对应实现和本机 SDK 的当前签名。

| 能力 | 已核对的入口／模式 | 执行边界 |
| --- | --- | --- |
| 鸿蒙命令桥接 | `HarmonyEngine.dispatch(json: String): String`，粗粒度命令、state／patch／outbound；`GatewayClient.action(command)` 执行平台 I/O | 不在 ArkTS 写第二套协议／Reducer；新增字段同步 Kotlin 与 ArkTS schema |
| 问答／审批 | `SharedQuestionStore.submitAnswer/submitCancel/responseReceived`；`SharedApprovalStore.submitDecision/responseReceived` | 保留已有请求归属、重复提交和过期校验，不增加自动允许 |
| 轨迹 | `SharedTrajectoryStore.replaceSession(sessionId, eventsJson)`、`receiveEvent(eventJson)`、`receiveEvents(eventsJson)` | 复用共享投影，按需构建，平台只展示 |
| 会话配置 | `SharedSessionControlStore.requestModels(sessionId, isConnected)`、`requestPermissionOptions`、`requestContextUsage`、`requestSessionStats` | `committed` 决定 patch 与 snapshot 的解码；沿用请求令牌，不把 patch 当完整快照 |
| 队列 | `SharedQueueStore.beginAction(sessionId, itemId, action)`、`acceptFrame(json)`、`takeDraft(sessionId)` | Host 确认后移除／回填，不能平台乐观删除后假装成功 |
| 上传 | `SharedFileUploadStore.bind`、`add(id,name,size,sha256)`、`chunkReady(token,data,bytes)`、`accept(frame)`、`timedOut(requestId)` | 平台持有私有副本并分块读；共享层推进确认偏移和 receipt |
| 文件 | `SharedWorkspaceFileStore.resolve(sessionId,path,requestId,supportsResolve,useCache)`、`download`、`acceptFrame`、`cancel` | 区分路径与 URL，复用共享完整性／路径规则 |
| 语音 | `SharedVoiceInputStore.open(context,currentDraft)`、`acceptJson(json)`、`cancel()` | 录音与授权是鸿蒙能力，不能假定 Android/iOS 音频 API 可直接使用 |
| 缓存 | `SharedChatHistoryCache.hydrateToStore`、`loadTypedPage`、`search`、`clear`；窗口与离线目录 Codec | Store 存在不等于鸿蒙数据库可构建；P6 专项先行 |
| UI 增量更新 | `ViewModels.ets` 的 `@Observed` 与卡片 `@ObjectLink` | 同 ID 不强制重建整个表单／消息，不丢局部交互状态 |
| 鸿蒙平台 | 现有 `CredentialStore` 的 Asset、`EntryAbility` 生命周期、`GatewayClient` WebSocket 已运行验证 | 新扫码／文件／录音／通知 API 必须在 P0 查证，不编造方法和参数 |

## 8. 用户最终试用路径

这条路径用于 P8-06，一条完整走通才说明“可以上手使用”，不是只查看页面截图。

1. 安装 HAP，首次进入能理解如何配对；扫码或手工连接真实 Host，取消和出错均可恢复。
2. 在首页辨认当前主机、切工作区、找会话、新建会话；主机切换后不会看到另一台的私有内容。
3. 连续聊天，阅读 Markdown／代码／表格，复制代码、展开思考／工具、查看轨迹，停止后继续发送。
4. 在手机内回答问题，查看完整审批信息并允许一次或拒绝；无需回到桌面完成基本交互。
5. 选择图片／文件发送，查看上传进度和回复中的附件／交付文件，能打开、预览和分享。
6. 使用模型、Agent、权限、队列及基准中的其余页面；设置改变与服务端一致，重启后本地偏好仍在。
7. 读历史时不会被新消息强拉到底；切会话、前后台、断网、恢复和杀进程后，消息与草稿按约定保留。
8. 断网仍能浏览和搜索已缓存内容；清理存储不会误删当前正在使用的文件。
9. 检查浅色、深色、横屏／平板、大字号、权限拒绝和减少动态效果；核心内容可读、控件可点、返回正常。
