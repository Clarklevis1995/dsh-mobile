# 会话输入框聚焦布局

Android 和 iOS 使用同一套状态与几何规格。

| 状态 | 显示内容 |
| --- | --- |
| 未聚焦 | 单行输入入口和添加附件按钮；隐藏发送、模型、权限及上下文工具 |
| 聚焦 | 输入区移到上方并占满宽度，底部显示附件、模型、权限、上下文及发送或语音操作 |
| 语音或待确认识别结果 | 保持展开，确保录音、切换键盘与确认结果可操作 |

- 底部加号、权限/模型/等级/上下文工具行和发送按钮共用同一条水平中轴；Android 的 42dp 工具槽位显式居中其内容，不以内容顶部作为对齐点。
- 切换约 220 毫秒，采用立即起步的缓出曲线；输入区连续移动和改变宽度，工具淡入淡出，外层高度平滑变化。
- 外框高度、内边距和加号位置由同一个连续进度计算；玻璃背景和裁剪边界也在同一动画范围内。加号始终保留，不采用退场后重新入场的过渡。
- iOS 在真正切换第一响应者、准备键盘前提交焦点状态（系统菜单查询 canBecome/ResignFirstResponder 时不写入焦点），缓存展开时的自然文本高度，避免逐帧重复测量 TextKit；两端在收起途中保留展开高度，避免单行预览导致外框先跳到紧凑尺寸。Android 的动画值只在测量/绘制阶段读取，覆盖层高度在列表测量阶段读取，避免输入区、菜单和会话内容逐帧重组。
- hint 与正文的内部对齐固定在顶部；收紧态的视觉居中由外层统一进度计算，焦点变化本身不提前更改垂直位置，避免动画开始前先跳一下。
- 保留同一个原生输入节点；失焦后不清空多行草稿、引用或附件，再次聚焦恢复完整编辑。
- 收紧时已有文字只展示一行，超长内容在末尾以省略号截断；截断只影响显示，不修改草稿或选区。
- 新增引用或成功加入附件时展开并进入文字编辑；收紧态点击加号仅打开菜单，打开/取消文件或图片选择器保持收紧。
- 图片缩略图最长边 72，按实际比例贴合预览行高度并顶部对齐，仅保留关闭按钮 5 点的边缘空间；附件到正文的间距为 6 点，横图不再被固定高度行上下居中撑出留白。
- 图片与文件预览先测量自然尺寸，再从零可见高度和零透明度展开，附件区间距与输入框共用 220 毫秒缓出时序；图片准备完成与聚焦状态在同一轮提交，首帧不能在加号旁先露出缩略图。
- 引用出现和移除使用同一段 220 毫秒缓出过渡：引用区高度、下方间距、透明度同时变化；正文与 hint 直接跟随逐帧布局，不再嵌套另一段位移动画。
- 引用 Cell 使用独立且稳定的 UI 标识，协议分段索引只用于删除请求；重复引用按实际点击的 Cell 区分。叉号与 Cell 共用生命周期，删除整项立即移除对应叉号，保留项只插值整张 Cell 的位置和宽度，右上角按钮不单独淡入或飞入。
- 引用预览：单条占满一行，两条各占半行，三条及以上使用三列等宽 Cell；每条最多显示两行摘要并可独立移除。引用区最多显示三行，超过九条后在固定高度内纵向滚动，新增引用滚到最新条目；删除仍按原始消息分段索引执行，不影响正文。
- 点击会话正文或退出键盘后恢复收紧态；收紧时发送和辅助工具不可被透明区域误触。
- iOS 减弱动态效果时使用更短的过渡；Android 遵循系统动画时长设置。

验证：两端逐帧比较引用区增高与原生编辑器位移（空草稿 hint、已有正文、插入及移除）；Android 真实触摸与键盘回归、窄屏、长草稿收起中间帧及加号节点连续性；iOS 11 个中间高度的原生视图边界、原生控件身份与多行草稿保留、深浅色渲染、实际会话页聚焦及正文点击收起，并逐帧检查实际录屏。测试不发送消息。
