## 设置中的实时网络检测

入口：Android/iOS **设置 → Mobile Gateway → 网络检测**。设置首页仍显示当前连接方式，并保留原有手动 Ping。

- 页面可见且 App 在前台时自动检测，1 秒采样，保留最近 60 秒；返回、关闭或进入后台即取消检测。再次进入或回前台重新开始，连接代际或传输方式变化也会清空旧统计。
- 显示实际业务连接方式、应用层 RTT、探测丢包率、延迟抖动、平均/P95 RTT、收发速率与成功/超时次数。延迟、丢包、抖动和收发流量各有实时折线图；蓝色为接收，橙色为发送。
- 探测通过当前业务控制通道发送，不经过单独的测速服务器。每次只允许一条在途探测，超时为 3 秒，严格匹配请求 ID，普通心跳、RTC 激活 Pong、重复和迟到回复均不会匹配新探测。页面退出或连接变化时丢弃在途探测，不记作超时。
- 探测丢包率是最近一分钟内已完成探测的超时/发送失败占比，并非底层 UDP/TCP 丢包率。RTT 包含网关处理和排队时间；抖动是连续成功 RTT 差值绝对值的平均，超时切断相邻关系。速率是应用层业务字节数（含探测），不包含传输协议开销，也不是可用带宽测速。
- **需同步更新网关**：本次为网关增加 `network-diagnostics-v1` 能力声明及 Ping `requestId` 回显。不支持的旧网关仍能连接与使用业务；检测页显示“网关需更新”，延迟/丢包显示 `—`，不误报为丢包。

手工验收：

1. 打开设置但不进入网络检测，确认没有 `requestId` 以 `network-check:` 开头的探测包。普通业务心跳会照常存在。
2. 进入检测页，等待数秒，确认连接方式与设置首页一致，RTT 和折线持续更新。切换四个指标，确认单位和收发颜色标识正确。
3. 返回设置或锁屏/切后台，确认不再出现新的诊断探测；再次进入/回前台应只有一组检测，旧数据已清空。
4. 使用隔离测试环境延迟或丢弃诊断 Pong，确认未满 3 秒不计丢包、超时后丢包率上升，恢复后 RTT 重新出现；普通 Pong 不能冒充诊断回复。
5. 分别测试 RTC、关闭 RTC 后的 WebSocket、RTC 失败后的 WebSocket 回退。断线或连接方式变化时不应混入上一段连接的数据。

## 2026-10-31 WS/RTC 切换的数据一致性

检查确认两种传输共用业务状态。现有同步层按 subscriptionId、streamId、seq 校验和去重，新连接 hello 会失效旧请求并恢复只读状态和订阅。本次修复旧 Socket 从异步 receive 返回后可能进入新 RTC 状态机的问题；补齐异步业务解码异常、RTC 状态回调、发送编码失败和大消息发送异常的连接归属检查，丢弃旧连接的迟到数据及错误。

已提交但未确认的消息、命令在传输切换时取消本地等待，并提供中英文“操作结果尚未确认”提示，不自动重放。新的历史快照不会自动清除该提示；它并不表示服务端操作被撤销或已失败，执行结果仍需结合恢复后的服务端状态确认。

最终在临时独立 iPhone 17 模拟器运行 49 项相关测试，0 失败：

- WS 已同步历史和增量，在新订阅快照及新增事件后仍完整接续；重复事件只产生一条记录，旧订阅的快照和增量被拒绝。
- 旧 WS 接收在切换时暂停、随后才返回，不会交给新 RTC 状态机；旧解码异常不向新连接发布错误。
- 旧 RTC 已提交的写操作及其迟到错误不在新 WS 重放，也不覆盖新状态。
- 未确认消息在重连、重新获取快照后没有再次发送，待确认提示保持有效。
- 同时复验原有前台、网络、控制请求恢复和 RTC 限时重试行为。

iPhoneOS arm64 按原有最低系统版本构建通过。测试使用本地回环 Socket、可控异步屏障及传输替身；本轮没有访问或重启用户网关，临时独立模拟器已经删除。上述验证不等于真机公网异常网络与服务端写操作事务保证。

新增提示的中英文资源和 JSON 格式已校验。全局 `scripts/verify-localizations.py` 仍报告当前工作区另外两条格式化文案 `%@：%@`、`%@：%@ · %@` 的既有译文缺失；本轮未覆盖这些其他改动。
