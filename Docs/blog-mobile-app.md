# 把 DeepSeek Harness 装进口袋：iOS 客户端功能全览

> Agent 在电脑上跑，你在手机上看。对话、轨迹、工作区、模型、权限——WebUI 上你会用到的东西，这里都有一份原生实现。

---

## 一、它是什么

用过 CLI 形态 Coding Agent 的人大概都有同一个体验：给 Agent 派一个稍复杂的任务，它开始读文件、跑测试、改代码，一轮下来三五分钟。这三五分钟里你被钉在电脑前——不是因为你要做什么，而是因为你**不知道它做到哪了**。

`DeepSeek Harness Mobile` 是一个原生 iOS 客户端。它通过 `dsh-plugin-mobile-gateway` 连上你电脑上的 Harness，把工作区、会话、实时回复和完整执行轨迹带到 iPhone 上。

- **iOS 17.0+**，仅 iPhone、仅竖屏
- 完整的**浅色 / 深色**双主题
- iOS 26+ 使用系统 Liquid Glass，旧系统自动回退到视觉一致的材质
- 通过 WebSocket 实时连接，**不是网页套壳**

## 二、工作区首页

打开 App 就是这一屏。深色模式下的背景是实时计算的液态流体 + 技术网格 + 点阵鲸鱼，和 Harness 官网同一套视觉语言。

### 会话列表

- 列出所有已知会话，按**最近活动时间**倒序
- 正在跑的会话显示 **"运行中"** 标记，其余显示相对时间（"3 分钟前"）
- 每个会话显示它使用的 Agent 预设
- 从未连接过时给出明确引导："暂无已知会话。连接服务后创建第一个任务。"

### 工作区切换

顶部下拉可以在多个工作区之间切换，也可以查看 **"未分组"** 会话（那些不属于任何工作区的会话，会显示"N 个未归属会话"）。

![切换工作区](images/screenshots/workspace-switcher.png)

### 浏览远端目录、创建新工作区

点"添加工作区"会打开一个远端目录浏览器——**浏览的是你电脑上的文件系统**：

- 逐级进入目录，可以用 ".." 返回上一级
- 显示完整面包屑路径和当前目录
- 隐藏目录标注为"隐藏目录"
- 在任意目录点"在当前目录创建工作区"即可建好

![选择工作区目录](images/screenshots/workspace-directory-picker.png)

### 搜索会话内容

首页有一个搜索框（"搜索会话内容"），支持**全文检索所有会话**，而不只是按标题匹配。找一句"上周那个改 CI 配置的对话"很有用。

### 设备连接状态

首页常驻一个连接指示灯，四种颜色对应四种状态：

| 颜色 | 状态 |
|---|---|
| 绿 | 已连接 |
| 黄 | 正在连接 |
| 红 | 连接失败 |
| 灰 | 未连接 |

## 三、设备配对：两种方式

首次使用需要和电脑上的 Harness 完成一次配对。

### 方式一：扫码

WebUI 的"移动设备"面板点"生成配对二维码"，App 里点认证按钮 → 扫描二维码。取景框有引导文案（"将二维码完整放入框内"），相机权限被拒时给的是可操作的提示而不是一片黑屏。

![深色模式配对](images/screenshots/pairing-dark.png)

### 方式二：手动粘贴

不想动相机（或者在模拟器上调试）时，可以直接粘贴 WebUI 给出的那串 Base64URL 配对字符串。这个界面会**实时反馈每一步的结果**：

- 正在连接 —— "正在提交一次性配对码并等待 Mobile Gateway 完成设备鉴权…"
- 连接成功 —— "设备鉴权已完成，长期 token 已安全保存到 Keychain。"
- 配对信息无效 / 连接失败 —— 给出具体原因

![浅色模式配对](images/screenshots/pairing-light.png)

### 配对之后

- 长期凭证保存在**系统 Keychain**，不进 iCloud、不进备份、不跨设备同步
- 之后每次启动直接自动重连，**不需要再扫码**
- 支持配对多台电脑（家里一台、公司一台），按地址分别保存，互不覆盖
- 网关关了又开、鉴权开关变动，App 会自动重连；只有凭证真正失效时才要求你重新配对

## 四、对话页

![浅色模式对话](images/screenshots/conversation-light.png)

这是使用频率最高的一屏。

### 实时看到 Agent 在想什么、在做什么

一次回复里你会依次看到：

| 内容 | 说明 |
|---|---|
| **推理过程** | Think 区块，实时逐字显示模型的思考 |
| **工具调用** | 工具名 + 参数，参数也是流式组装出来的 |
| **工具结果** | 执行结果预览，失败会明确标为"工具失败" |
| **正文回复** | 最终答案，完整 Markdown 渲染 |
| **上下文注入** | 由插件注入的额外上下文，标注来源 |

流式阶段先用纯文本快速呈现，生成完成后自动换成完整排版。

### Markdown 与代码

- 完整 Markdown：标题、列表、引用、表格、链接
- **代码块带语法高亮**
- 行内代码有独立的圆角背景样式
- 长回复滚动流畅，不会因为反复解析而卡顿

### 输入与发送

底部输入框（"描述你想要构建的内容"）支持多行输入，会随内容自动增高。点击对话区空白处收起键盘——而且**不会吃掉你原本想点的链接或按钮**。

### 智能吸底

这是很小但很影响体验的一点：

- 你停在底部时，新内容自动跟随
- 你**主动往上翻看历史**时，App 立刻停止抢夺滚动位置
- 此时右下角出现"滚动到最新消息"按钮，你想回去再回去
- 在底部继续下拉产生的回弹**不会**被误判成"离开了底部"

### 历史记录分页

打开一个长会话时会自动加载最新一批历史，并显示进度（"正在加载历史记录 · 1200/3400 个事件"）。往上滑动会自动继续加载更早记录，也可以点"加载更早记录"手动触发。加载历史时**实时生成不会被卡住**。

### 会话执行状态

点顶部的状态条会展开一个完整的统计面板：

**执行**
- 轮次、步骤
- 工具调用耗时
- 首 token 平均延迟
- 解码吞吐（tok/s）

**Token 用量**
- 输入、输出
- 缓存读取、缓存写入
- 推理 token
- **缓存命中率**

**上下文**
- 当前压力
- 预计用量
- 上下文窗口大小

输入框旁边还有一个上下文使用率的环形指示器，一眼就能看出"这个会话快撑不住了"。

### 会话内切换模型与权限

不用回电脑，在对话页就能改当前这个会话的配置：

- **模型**：按 Provider 分组列出所有可选模型
- **推理等级**：低 / 中 / 高
- **权限**：只读 / 工作区写入 / 完全访问

### 新建会话

新会话页面会显示即将使用的默认 Agent 预设、默认模型和默认权限，让你在发第一句话之前就知道它会以什么身份运行。预设有对应的中文名：标准模式、PTC 模式、极简模式、创造模式。

## 五、轨迹页

![浅色模式轨迹](images/screenshots/trajectory-light.png)

对话页回答"Agent 说了什么"，轨迹页回答"Agent 究竟做了什么"。两页可以左右滑动切换，**各自保留滚动位置和展开状态**。

### 顶部时间线总览

一条压缩的执行时间轴，横轴是时间，纵向分三条泳道：

- **Input** —— 你的输入
- **Model** —— 上下文注入、模型请求、Assistant 回复
- **Tools** —— 工具调用与子工具调用

旁边是 `Duration` / `N Turns` / `N Calls` 三个总计。**点击时间轴上任意色块，下方列表会自动滚动并高亮那条记录**——想找"那个跑了 8 秒的工具调用"，直接点最宽的那条。

时间轴刻意做了压缩：轮次之间的空闲等待不计入时长，所以短的工具调用不会被长时间的空等挤成一个看不见的细线。

### 事件列表

按类型着色分类：`USER` / `CONTEXT` / `REQUEST` / `ASSISTANT` / `TOOL` / `SUBTOOL`，模型请求会编号（Request #1、#2……）。

### 单条记录详情

点任意记录会从底部弹出详情面板，按类型提供不同的分页：

| 记录类型 | 可查看内容 |
|---|---|
| 用户 / 上下文 | 摘要、预览、原始数据 |
| 模型请求 | 摘要、模型选项、Token 用量、耗时 |
| 工具调用 | 摘要、**完整参数**、**执行结果**、工具 Schema、耗时 |

工具还在跑的时候，结果区会显示"等待工具返回…"，跑完没有输出则显示 `(no output)`。这是排查"Agent 为什么做错了"最有用的地方——你能看到它调工具时**实际传了什么参数**。

![轨迹详情](images/screenshots/trajectory-detail-light.png)

## 六、全局默认配置

![设置](images/screenshots/settings.png)

设置页管的是**新建会话的默认值**，并且和 WebUI 读写同一份部署级配置——在手机上改完，回电脑上依然生效。运行中的会话保持它启动时的配置不受影响。

### Agent 预设

![Agent 预设](images/screenshots/agent-presets.png)

预设决定 Agent 使用的工具、提示词与能力组合。列表里可以看到：

- 每个预设的名称与说明
- 当前正在用的那个标为"当前使用"
- 配置有问题的预设会明确标注"该预设存在配置错误，暂时不能设为默认值"
- 服务端是否支持自定义预设、是否提供配置文档，都有对应提示

设为默认前会二次确认，并说明"这会更新部署级设置，并同步影响 WebUI"。

### 默认模型与思考等级

![默认模型](images/screenshots/default-model.png)

按 Provider 分组浏览所有可用模型，选定后再选思考等级（低 / 中 / 高）。同样有当前值标记和修改前确认。

### 默认权限

四档，每档都有说明：

| 权限 | 含义 |
|---|---|
| 每次询问 | 需要写入或执行敏感操作时请求确认 |
| 只读 | 允许读取工作区，不允许修改文件 |
| 工作区写入 | 允许在当前工作区内读取和写入 |
| 完全访问 | 允许不受沙箱限制地访问宿主环境 |

改动权限这种有安全含义的操作，一律弹确认框。

### 连接与宿主信息

- 手动连接 / 断开连接
- **Ping 网关**，验证链路是否真的活着
- 查看宿主 Harness 版本、已连接会话数

### 外观

跟随系统 / 浅色 / 深色，三选一。

## 七、深色模式

![深色模式对话](images/screenshots/conversation-dark.png)

不是给浅色配色加个滤镜。每一屏都单独调过——包括气泡在深色下用更高的透明度以保持同样的层次感，包括扫码页、配对页、轨迹详情面板这些容易被忽略的角落。首页的深海蓝、水波纹、技术网格和点阵鲸鱼，构成和 Harness 官网一致的氛围。

## 九、怎么用起来

### 你需要

- 一台运行 DeepSeek Harness 的 macOS，且已装好 `dsh-plugin-mobile-gateway`
- 一台 iOS 17.0+ 的 iPhone（或模拟器）
- 手机和电脑在同一个可互访的私有网络里（同一 Wi-Fi，或通过 VPN）

### 步骤

1. 电脑上启动 Harness，确认插件已加载
2. Xcode 打开 `DeepSeekHarnessMobile.xcodeproj`，选 `DeepSeekHarnessMobile` scheme 运行
3. WebUI 左下角"移动设备"面板 → 开启"允许移动设备连接" → 生成配对二维码
4. App 首页点认证按钮 → 扫码（或粘贴那串 Base64URL）
5. 面板里设备显示"在线"，即完成

### 连接地址

| 场景 | 地址 |
|---|---|
| iOS 模拟器 | `ws://127.0.0.1:3080/ws/mobile` |
| 同局域网的 iPhone | `ws://<Mac 的局域网 IP>:3081/ws/mobile` |
| 公网部署 | `wss://<your-domain>/ws/mobile` |

> 真机上 `127.0.0.1` 指的是手机自己，必须用 Mac 的局域网 IP。公网部署要在网关前配 TLS 反向代理。

配对二维码一次性使用、5 分钟过期。配对成功后凭证进 Keychain，之后启动直接重连。
