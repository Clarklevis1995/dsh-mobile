# 手机连接器实现与联调

本次实现包含网关的「设备权限」页、App 侧栏的「连接器」页、逐设备/逐主机持久开关、手机操作自动同步网关权限，以及 Agent 到手机原生能力的反向调用。通讯录不注册、不请求权限、不执行读取。

## 当前交付范围

| 能力 | iOS | Android |
| --- | --- | --- |
| 日历 | 忙闲查询；在默认可写日历新建日程，可设全天、地点、备注和提前提醒，不发送邀请 | Calendar Provider 忙闲查询；未提供写入 |
| 提醒事项 | 查询未完成事项；在默认列表新建待办，可设截止时间、到点通知和优先级 | 暂不可用；不把事件闹铃当作独立待办 |
| 位置 | 前台单次近似/系统授权精确位置；地点搜索、地址转换、驾车/步行路线及苹果地图跳转 | 前台单次近似位置，同样限制精度与时效 |
| 照片 | 系统选择器选择一张，修正方向、缩放、重新编码，选中后直接回传 | 系统图片选择器选择一张，修正方向、重新编码，选中后直接回传 |
| 音乐 | 已授权本地音乐库搜索、系统播放器状态、播放/暂停/定位 | 暂不可用；没有申请通知读取或无障碍权限来代替播放器接入 |
| 健康 | HealthKit 步数及睡眠摘要，用于日常健康回顾 | 暂不可用；Health Connect 适配另行实现 |
| 闹钟 | iOS 26+ AlarmKit 一次性闹钟，创建、查询和取消当前主机通过 Whaleness 创建的闹钟 | 未声明此能力 |

iOS 七类能力已接上原生接口，闹钟在 iOS 26 以下禁用。Android 三类不可用能力在页面禁用，并向网关报告 unavailable，避免假连接。照片为有界缩略图版本：最长边 768 像素、JPEG 不超过 64 KiB、每次一张；不支持整库语义搜索、原图或视频。健康查询的时间窗最多 8 天，返回该窗合计；不写入健康数据，不做诊断。

## 开启与调用

1. 同时更新移动 App 和本地网关包，重新加载 DSH。网关 bundle 新增 `mobile-phone-tools` 插件行，入口为 `dsh-plugin-mobile-gateway/phone-tools`，注入宿主的 `tools`、`attachments` 与 `systemPrompt`。
2. 在 App 侧栏「连接器」中开启本机能力，完成系统弹窗。App 自动同步该设备的网关权限，无需再去网关开一次；关闭也会同步。设置按当前主机 ID 隔离，切主机不复用另一主机的开关。
3. 网关「移动设备 → 设备权限」同步显示权限，仍可直接撤销。权限写入原有设备注册表，重启保留；重新配对时清空原授权。网关撤销后手机开关显示关闭，用户再次手动开启才会恢复；普通重连和 App 重启不会自动恢复撤销的权限。
4. 手机发起的请求自动绑定已鉴权连接的设备和网关。Agent 首轮上下文即可看到来源及已开启能力，直接调用 `phone_reminders_list`、`phone_calendar_busy`、`phone_location_current` 或 `phone_health_daily_summary`，无需先枚举设备或填写 `deviceId`。其他能力使用 `phone_tool`，同样自动绑定来源。桌面发起且没有手机来源时，才调用 `phone_devices` 并显式指定设备。Agent 的会话 ID、工具调用 ID 和取消信号来自 DSH 的执行上下文。
5. 手机必须在前台。开启连接器即持续授权当前主机，已授权调用自动执行并回传结果，不再逐次确认或预览。照片仍由用户在系统选择器中选取，选中后直接回传缩略图。关闭开关、网关撤权、超时或失去当前租约即终止。

网关「可信设备」与「设备权限」共用全部有效配对设备，均包含离线设备、在线优先，并显示相同设备总数。「可信设备」支持逐项勾选、全选和批量删除。删除后两页同步移除，清除对应权限及凭据，取消在途连接器调用并断开该设备的全部连接；其他设备保持原样。批量保存失败则整批回滚，不提前断开连接。删除后的设备需要重新配对。

管理页的设备列表与网关状态独立加载，哪个先返回就先显示；「可信设备」的刷新与删除后更新仅请求设备列表。同类读取尚未结束时复用已有请求，不随每三秒轮询叠加；读取及响应体解析设五秒超时，失败显示可重试状态并保留已显示数据，关闭面板取消未完成读取。权限或设备发生修改后，过期读取结果不能覆盖新状态。此超时只用于管理页这两类读取，不改变配对、删除、连接器调用或隧道配置的执行时限。

手机请求直接调用 `phone_calendar_busy` 的参数：

```json
{
  "start": "2026-11-10T00:00:00+08:00",
  "end": "2026-11-11T00:00:00+08:00"
}
```

`phone_tool` 允许的原生工具为 `calendar.busy`、`calendar.create`、`reminders.list`、`reminders.create`、`alarms.create`、`alarms.list`、`alarms.cancel`、`location.current`、`location.precise`、`maps.search`、`maps.geocode`、`maps.reverse-geocode`、`maps.directions`、`maps.open`、`photos.select`、`music.search`、`music.state`、`music.play`、`music.pause`、`music.seek`、`health.daily-summary`。没有任意命令执行接口。日历、提醒和健康的范围读取要求带偏移的 start/end 及 IANA timeZone；最长 8×24 小时。手机消息携带的 `clientTimeZone` 可作为缺省 timeZone，因此上例无需重复提供；桌面无来源时必须提供。音乐播放可指定搜索返回的 itemId；定位播放进度使用 seconds。

同一个 DSH 进程有多个网关实例时，手机请求按真实来源的 `gatewayId` 路由；若另有插件配置且与来源冲突，返回 `gateway_source_mismatch`。桌面无来源时才需要配置 `gatewayId` 区分多个网关，否则返回 `gateway_selection_required`。没有手机来源且没有显式设备 ID 时返回 `device_not_bound`，不会猜测唯一在线设备。

## 请求来源与响应速度

来源链路为：已鉴权连接的 `deviceId`/`gatewayId` → 请求准入记录 → 宿主入队消息的 `source.rpcId` → 宿主生成的稳定 `message.id` → 实际出队及本步消费的消息。连接器插件监听 `agent/inbox/claimed`，使 SDK 在 `agent/pre-step` 之前组装首轮上下文时就能识别来源；随后以实际进入本步的消息再次校验。用户正文不插入设备标记，不更改已有 requestId，不接受消息体自行声明的 deviceId/source。

来源按实际消息绑定，不使用“该会话最后发送消息的手机”。多台手机排队不会相互覆盖；同一步混合不同设备或手机与桌面输入时，返回 `request_source_ambiguous`；新桌面输入不会继承上轮手机。来源信息只在当前进程中保存，不扫描历史恢复。来源手机离线则报错，不自动换成另一台在线手机；模型传入不同 deviceId 也会被拒绝。

模型上下文提示手机数据优先使用相应连接器，明确指定飞书等服务时保留指定数据源。四个快捷工具将发现设备和通用工具参数选择收敛为一次调用，减少额外模型往返；模型理解与生成答案仍有自身耗时。

网关增加不含参数或结果的 `phone-tool` 计时日志。`phase:start` 中的 `sinceMessageMs` 是消息准入至工具调用的总时长，可能包含排队及先前步骤；`sinceStepMs` 是本步准备完成至工具调用的时长，不等于纯模型思考时间。`phase:end` 中 `elapsedMs` 是调用至完成的总时长，包含网络、手机原生查询；照片还包含系统选图及附件保存。这些日志用于区分调用前等待和调用本身耗时，不能单独拆出原生 API 耗时。尚未使用用户真实数据测量此次响应速度。

上述来源路由与快捷工具只修改网关。当前 App 已发送 requestId 和 clientTimeZone，无需为此增加新协议；更新网关并重新加载 DSH 后，新发送的消息生效。

## 数据和权限链路

`Agent 工具 → 当前进程中指定网关的 broker → 已配对控制连接 → App 本机开关/系统权限/持续授权 → 原生查询 → 同连接/租约回包 → Agent 工具结果`

网关只在配对成功的 hello 中声明 `device-tools-v1`。手机注册模块 enabled/available 状态及可选 tools 白名单，网关分配连接租约。新连接或重新注册使旧租约及在途请求失效；旧连接不能在新连接断开后重新接管。结果必须同时匹配设备、当前连接、租约、调用 ID。

手机注册帧可选携带本次用户明确操作的 `permissionChanges` 布尔补丁，注册回执新增 `permissionSync: true`。网关在校验配对设备、控制连接、连接代次、能力版本、模块白名单后，仅写入该连接所属设备；开启还要求手机报告 enabled/available。普通注册没有补丁，不根据已保存的 enabled 值推导授权。保存失败返回 permission_save_failed，不回成功确认。

App 等待回执后显示主机实际状态，同步中暂禁重复操作；页面仅保留原生图标、能力名称和开关，旧网关没有 permissionSync 回执时弹窗提示更新。超时或错误只重新读取状态，不重发已经发送的开启意图，防止覆盖后来发生的网关撤权。离线的未发送修改在本次 App 运行恢复连接时发送；重启 App 后以网关实际状态为准。用户可在手机同一个开关重新开启来重试，无需到网关操作。

网关模块授权默认关闭；手机开关默认关闭。`POST /mgw/devices/:id/permissions` 只接受七模块的布尔补丁，复用现有管理面本机访问与 Origin 校验；保存失败恢复原内存值。权限关闭立即取消对应在途调用。App 关闭开关、切主机、连接断开、进入后台、主机撤权和 120 秒调用超时均取消；迟到回调不会进入后续调用。

照片是用户通过系统选择器明确选取后重新编码的缩略图，不增加二次预览或发送确认。控制回包严格限制为 128 KiB；图片 base64 不超过 64 KiB 原始字节。工具插件通过宿主 `attachments.saveImages` 验证并落成持久图片引用，工具结果交给模型与聊天 UI 的是原生 image block，不把 base64 文本塞进模型上下文。图片可能随主机会话保留，依照已授予当前主机的照片连接器权限处理。其他结果限定字段及条数，不允许伪造附件字段混入日历或健康结果。

音乐控制会改变系统播放；iOS 按主机保存最近 512 个 session/toolCallId 的执行尝试，避免同一调用自动重放。播放回包标识请求及观察到的状态，不能视作远端音频已经成功播放的保证。

## 系统与运行边界

- 连接器只响应前台请求；不会因服务器发来工具调用而保证唤醒已挂起/被杀的手机，也不依赖后台保活。服务器 Agent 的长任务仍在主机继续，手机离线则返回 device_offline/user_action_required。
- iOS 日历和提醒使用 iOS 17 的 full-access API，旧系统使用 EventKit 兼容 API；目前按明确指令支持新建日程和提醒事项，不开放编辑或删除既有日程。
- HealthKit 已补 entitlement 和读取用途文案（[Apple 授权说明](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)）。真实设备签名需要对应 App ID/描述文件开启 HealthKit。完成系统授权弹窗不能证明读取获准；无记录返回 null 与 no-data-may-mean-not-shared，不冒报 0。发布时应让隐私政策及 App Store 隐私声明覆盖向用户选定主机/模型服务传输摘要的用途。
- 不后台定时上传、不缓存完整日历/健康记录、不读取通讯录。主机收到的结果可能进入主机历史及模型服务。

本实现相对原设计的收敛：逐模块权限代替额外总开关；同包 phone-tools 子入口代替独立 npm 包；图片先交付单张 64 KiB 缩略图协议，未实现 3 张原图的分块上传；未加入日历/提醒列表的逐来源选择、完整 Apple Music 目录、Android Health Connect/播放器/提醒适配。后续扩展不应绕过现有三层权限。启用连接器代表对当前主机持续授权，用户可在手机或网关撤销，普通重连不会自动恢复撤销的权限。

# 在线状态与能力登记

手机连接器页仅保留「连接器状态」入口和状态指示灯，点击进入独立状态页面。绿色表示网关已确认登记，灰色表示未连接，橙色表示注册中、不支持或未确认，红色表示注册失败、超时或已连接但未注册。详情状态来自当前主机的登记回执与只读状态查询；确认成功后显示能力总数、最近确认时间，并可展开按模块查看网关实际接受的动作。关闭、不可用、主机未允许的模块分别标识，登记成功不等于所有模块均获准执行。刷新状态及重新注册操作均在详情页。

新版网关通过 device-tools-registered 回传实际接受的 modules/tools，声明 statusQuery=true。页面显示时每十秒查询当前控制连接登记，刷新等待五秒；后台不发送查询，离开页面停止轮询。查询不更换租约、不重新授权、不取消执行。手动重新注册仅在当前没有连接器任务执行时进行，不重放以前的开启权限补丁。旧网关未返回有效清单时保持未确认，不使用手机声明的能力推断成功。断线、失败、超时或登记丢失后移除当前展示的确认清单，防止旧成功状态残留。

设备在线表示鉴权连接存在；连接器可调用还要求当前控制通道成功提交 device-tools-register 并取得租约。网关返回 connectorStatus=ready/not-registered/offline；在线但未登记返回 connector_not_ready，不能解释为手机关机、未解锁或一定在后台，也不能从空 tools 推断手机不支持曲库等能力。模型遇到未就绪或离线不反复调用同一手机或执行 shell 等待。

能力登记只保存在当前网关进程内，控制连接断开、网关停止或重启、设备撤销时移除，重连由手机重新登记。会话通道单独关闭不删除控制通道登记，旧连接关闭不能删除新连接租约。持久化设备权限不随临时登记清空。注册校验失败保留已有有效登记，从未登记成功时仍为空。

为兼容新手机，网关接受同模块内格式正确的新工具名称，只登记自身认识的工具；未知工具永不暴露或调用。非法格式、重复、错误模块及通讯录工具仍拒绝。运行进程不会因本地源文件更新自动替换模块缓存，部署后须重启 DSH 网关并让手机重连。

注册诊断日志仅记录设备 ID、通道、修订及错误码，不记录查询参数、结果或凭据。手机收到注册版本或参数错误时提示检查网关兼容性，登记恢复后清除旧提示。
