# 输入栏键盘避让与收起发送

更新日期：2026-11-12。

## 行为

- Android、iOS 输入栏收起后，只要仍有文字、引用、图片或文件草稿，就显示原有发送按钮并预留按钮宽度。发送沿用原有发送、禁用、防重复提交和草稿清理逻辑；空草稿恢复原有外观，停止生成入口保留。
- iOS 使用系统 `UIKeyboardLayoutGuide` 检查当前页面仍被遮挡的区域，补偿 SwiftUI 尚未避让的部分，不重复增加整段键盘高度。输入法切换时布局指南尚未更新，则使用系统键盘区域通知，并转换到当前窗口坐标。
- 探针与输入栏使用相同的底部安全区范围，避免少算 Home Indicator 区域。额外避让量限制在可用高度内，任务区高度随剩余空间调整。
- iPad 浮动键盘不整页上推；窄窗口、横屏、外接键盘工具栏按当前视图与实际键盘区域的交集计算。
- Android 继续使用 `imePadding` 和系统窗口 Insets 处理九宫格、候选栏、表情面板等高度。输入法切换短暂报告隐藏时，延迟确认失焦，避免主动打断输入连接。
- 修复 Android 编辑器重新挂载时，将初始化空值当作编辑回传、覆盖刚回填的语音草稿的问题。初始化快照不再回传，后续原生编辑和外部草稿更新仍同步。

## 验证

iOS 验证了 360、480、240、84、0 pt 系统键盘区域变化，以及自动避让充分/不足、浮动键盘、硬件键盘工具栏和收起布局。实际 App 界面测试确认保留草稿、失焦收起输入栏后发送按钮仍可点击、文字不与按钮重叠；后续一轮因模拟器中无已有会话而跳过了该 UI 用例。

最终结果：iPhone 8 项布局测试、iPad 3 项键盘布局测试通过；Android 299 项单元测试通过。22 项相关 Android 设备用例分批均通过，其中整组运行时两项截图/层级用例出现稳定性问题，独立重跑均通过。

Android 设备测试包含 240、420、560、84、0 dp 的 IME Insets、收起发送回调与草稿清理、输入框节点和文本保留、语音回填、附件粘贴和展开/收起动画。具体执行结果见 `build/verification/composer-keyboard-2026-11-12.json`。

未在安装搜狗等第三方输入法的实体设备上验证；多档高度验证使用系统区域事件/Insets。模拟器无法直接呈现自定义软件键盘的单元测试已改为通过系统区域事件验证实际布局更新，不将此结果等同于第三方输入法实测。

本次未新增产品文案。全项目本地化守卫当前被另一个地图改动中的四处文案阻断：`MapAppPicker.kt` 的“高德地图/百度地图/谷歌地图”和 `SharedMapLinks.kt` 的“我的位置”。这些文件未在本次输入栏修复中修改，单元测试与守卫结果分开记录。

系统行为参考：[Apple UIKeyboardLayoutGuide](https://developer.apple.com/documentation/uikit/uikeyboardlayoutguide)、[浮动键盘跟踪设置](https://developer.apple.com/documentation/uikit/uikeyboardlayoutguide/followsundockedkeyboard)。
