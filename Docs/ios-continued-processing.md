# iOS 持续后台处理接入

更新日期：2026 年 11 月 8 日。

iOS 26 及以上在用户前台发送消息或提交问题答案时申请 `BGContinuedProcessingTask`。任务用于继续同步这次用户发起的 Agent 工作，不用于空闲连接、自动发现的远端任务或后台定时唤醒。旧系统继续使用现有有限后台额度及定位、音频策略。

实现位于 `Core/AgentBackgroundExecutionController.swift`，通过 `AgentContinuedProcessing` 隔离系统 API。AppStore 将真实会话事件和流式进展交给控制器，进度只在收到事件时更新，没有按时间递增的假进度。回合总长度未知，进度单位是已同步的事件，并保留一个未完成的回合单位。

申请使用每次唯一的标识符，Info.plist 配置 `$(PRODUCT_BUNDLE_IDENTIFIER).agent.continued.*`。使用 `.fail` 策略，系统无法立即执行时沿用原有机制，不排队延迟启动旧任务。iOS 27 使用异步提交接口，并核对申请身份，避免已经结束的请求留下后台任务。

普通 `beginBackgroundTask` 到期时，如果持续任务仍在运行，仅结束有限额度，不清除活动回合。任务结束、连接取消或会话快照确认已停止时，释放持续任务。系统资源回收和用户点击系统卡片的停止按钮都会触发到期处理：清理本地保活和跟踪状态，不重复申请，不重发消息，也不向远端发送 Agent 停止命令。远端任务继续由主机管理。

该接入没有修改现有定位和音频优先级。系统可以拒绝或提前终止持续任务，不能据此承诺固定几十分钟或永久后台执行。参考 [Apple 持续后台任务说明](https://developer.apple.com/documentation/backgroundtasks/bgcontinuedprocessingtask)。

## 验证范围

自动测试覆盖前台用户操作准入、普通额度到期与持续任务共存、持续任务到期后的资源清理，以及会话进度和快照结束。

真机验收需要使用无调试器的签名 Release 包：

1. 前台发送任务，确认系统任务卡片出现；切后台并锁屏，观察真实流式和工具事件是否持续同步。
2. 完成或断开连接后检查卡片和保活资源释放。
3. 点击系统卡片停止，确认本地后台额度结束，远端任务没有被取消，且没有新卡片自动重建。
4. 验证系统拒绝请求时仍按旧机制运行；打开已有远端任务和仅保持空闲连接不产生持续任务卡片。
5. 在 iOS 16.1 至 25 回归旧后台机制。持续执行时长、耗电和资源紧张下的行为以真机记录为准。
