# Android 开关规范

- 所有应用内二态开关统一使用 `DshSwitch`，保持与 iOS 一致的胶囊轨道、白色滑块及动画；业务页面不要使用 Material `Switch` 或平台默认开关。
- 替换开关时保留原有回调、禁用条件、无障碍语义和外层整行切换逻辑。异步操作等待期间需要保持原色时使用 `preserveDisabledColors`，仍然禁止重复点击。

# Android 菜单规范

- 所有应用内菜单必须使用项目统一的 `DshMenu`、`DshMenuItem`、`DshMenuPopup` 和 `DshMenuSurface` 组件，沿用圆角毛玻璃、轻阴影及淡入缩放动画。
- 禁止在业务页面直接使用 Material `DropdownMenu` / `DropdownMenuItem`、平台 `PopupMenu`、自行绘制的 `PopupWindow` 菜单或系统默认文字操作工具栏。
- 特殊锚点、箭头面板、横向文字工具栏可保留业务定位逻辑，但必须复用统一的菜单容器、菜单项和背景采样宿主。
- 输入框及正文的文字操作保留原生选区、手柄、剪贴板和编辑行为，操作菜单使用项目组件。
- 原生网页必须使用 `DshMenuWebView`，将浏览器文字选择动作交给项目菜单组件，不能直接实例化 `WebView`。
- 新增页面和独立窗口必须接入 `DshMenuHost`，以获得真实背景模糊与统一文字操作菜单。
- 修改菜单时检查窄屏边界、长菜单滚动、禁用项、返回键/点击外部关闭、危险操作和文字选区焦点。

# 底部面板布局与滑动

- 禁止在 `ModalBottomSheet` 外层组合 `fillMaxHeight()` 与顶部 `padding` 来限制可见高度；保留原生窗口约束，在内容层限定目标高度，避免背景圆角与内容在拖动时分离。
- 拖动条、标题和正文必须共用同一面板容器。窗口边距明确分配，不能用随拖动偏移变化的顶部留白补偿位置；长正文只在分配给正文的剩余高度内滚动。
- 修改面板高度或手势后，必须验证手指尚未抬起的上下拖动：背景顶边与标题同步位移，长正文滚动时标题和面板顶边不漂移，静止时底边覆盖到系统导航区域。不能只验证手势结束后的截图或内容区域坐标。
- 要求列表与面板独立滚动时，必须隔离列表边界处两个方向的剩余位移和 fling 惯性；保留列表自身的滚动与惯性，以及从标题或拖动条发起的面板拖动。验证长列表到底后连续快速上滑、到顶后连续快速下滑，并逐帧检查标题和拖动条位置，不能仅检查最终停稳的位置。
