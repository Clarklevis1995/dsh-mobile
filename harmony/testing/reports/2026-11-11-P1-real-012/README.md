# 真实网关 0.12 交互与冷启动回归

2026-11-11，API21 ARM64／Mate70Pro模拟器，独立 smoke 包；真实 DSH 0.2.2-rc.1、mobile gateway 0.12.0、临时工作区和独立观察器。受控模型仅运行本地适配器，问题、审批、写文件、事件持久化仍经过真实 Host／Agent 服务；未访问用户3080系列端口。无真实设备结论。

## 已通过 G

- business：原生发送、流式、停止、三题单选／多选／自定义回答、中文Markdown工作区文件下载预览，Asset身份重连与加密草稿恢复。该轮冷启只读回草稿，不包含继续发送。
- approvals：ALLOW／REJECT／EXTERNAL／REPLAY 四项。未决定时目标文件不存在，单次允许后只有对应标记文件落盘，三项拒绝均无文件。全局权限始终 read-only。冷启动重放同一 rpc，外端处理后移除入口。
- 原始审批审计通过 callId 关联 ApprovalService 的 asked／decided，网关 approvalId 与内部审计id不相同；逐个压缩帧解码，只归档相关两种事件。每项只有一次最终决定。
- questions：取消、冷启动同rpc重放＋外端回答、随后发送新消息并取消Agent，三项全部通过；每个标记在真实历史恰好一条用户消息，过期表单移除。

## 发现并修复的冷启动发送缺陷

旧 Native 每次新实例从 harmony-1 编号，Host消息幂等缓存会把新请求误认旧消息，表现为收到 sent 但不开始新轮。真实问题专项第三项先失败；新增16个新Engine同session的K红测，修复前失败。现在每实例128bit随机命名空间＋递增序号，保留请求幂等语义而避免跨实例冲突。

修复后105 JVM／53 Node、release Native与HAP构建通过，新副本实际完成 questions 三项，第三项明确发生在杀进程重启之后。原始红／绿日志随附。审批四项由修复前104版本通过，未据此声称审批后续所有发送边界已关闭。
